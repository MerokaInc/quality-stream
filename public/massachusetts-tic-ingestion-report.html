Architecture Roadmap

Recommended PR sequence for the existing Redshift and Glue architecture

The recommended implementation unit is one new `tic` source module plus small serving marts, not a giant one-shot PR. The sequence below follows the conventions in `m-alpha/CLAUDE.md`, `pipeline/README.md`, the current consolidated Redshift builders, and Step Functions orchestration.

Key architectural constraint: keep full granular TiC rate facts in Unified Iceberg first. Use Redshift for inventories, registries, Massachusetts market summaries, and benchmark marts. Do not try to make Redshift the first landing zone for every raw negotiated rate row.

Payor Breakdown

One card per payor program, including a pie chart for each

Each card shows claims priority, plan topology, file mix, direct links, and the operational issue that matters most. The pie chart on each card is the current file mix for that payer: in-network versus allowed-amount files, or unresolved versus known where the source is still blocked. In TiC, `allowed amount` means the historical out-of-network amount the insurer treated as payable, not the billed charge and not an in-network negotiated rate.
